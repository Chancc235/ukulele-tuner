# PWA 测试计划

## 1. 自动测试层

使用 Node 内置测试工具，不依赖浏览器和麦克风：

- 规格一致性：JSON 与 JavaScript 四弦频率、阈值一致。
- cents：无效输入、正负方向、±5 边界。
- 自动目标：G/C/E/A、最大匹配距离。
- 手动目标：永不自动换弦。
- YIN：四目标纯正弦、±10 cents、强二次泛音、静音、低音量、NaN。
- 稳定器：中位数、EMA、离群点、目标切换、准音滞回、超时。
- 文件聚合：多窗口目标计数、中位数、无可信窗口。
- 麦克风：恢复不阻塞权限请求、授权后再次恢复、恢复超时、取消等待、晚返回的流、旧请求隔离、中断、时钟冻结、系统静音、轨道结束和帧处理异常后的清理。
- Service Worker：预缓存清单包含所有必要静态文件，cache version 合法。

命令：

```bash
npm test
npm run check
```

## 2. 桌面浏览器功能测试

可重复执行的集成测试：

```bash
npm run test:browser
```

脚本使用 Node 内置工具、Chrome DevTools Protocol、临时浏览器配置和合成 WAV，不依赖第三方 npm 包、不读取真实麦克风。默认启动 macOS Google Chrome，可用 `UKETUNE_BROWSER_PATH` 指定其他 Chromium 路径；本次已验证 macOS Chrome，未把该脚本加入 Linux CI。

- 在同一浏览器安装旧版 `399a0a1`，切换到当前源码，验证更新提示、点击更新、版本号和旧缓存清理。需要本地包含旧版 Git 历史；可设置 `UKETUNE_PREVIOUS_REF`。
- 经真实 `getUserMedia → AnalyserNode → YIN → UI` 输入 C/E/G/A 正弦波，等待稳定读数在目标 3 cents 内且显示“准了”。
- 验证无声提示、停止释放资源、音频中断、授权后恢复、取消权限等待和晚返回流清理。
- 模拟拒绝权限，验证重试和录音入口可用；恢复授权后再次识别 C4。
- 通过真实文件输入选择 C4 WAV，验证本地解码和结果。
- 断开浏览器网络并关闭测试服务器，重新加载缓存页面，再用模拟麦克风验证离线调音。
- 检查未捕获异常与手机宽度下的横向溢出，保存临时截图。

这种浏览器 API 模拟用于验证应用面对不同 API 行为时的处理流程，参见 [Playwright 官方模拟说明](https://playwright.dev/docs/mock-browser-apis)；本项目脚本直接使用 Chrome DevTools Protocol，并未引入 Playwright。

另需按实际浏览器和文件补充以下手工检查：

- 本地页面无控制台错误。
- 自动/G/C/E/A 按钮状态和键盘操作正确。
- 麦克风允许、拒绝、开始、停止、重复开始。
- 选择 WAV/MP3 测试夹具后显示进度和结果。
- 文件过大、格式错误、纯静音有清晰错误。
- 切换页面可见性后释放麦克风。
- 无录音 fetch/XHR 请求。
- Service Worker 在受支持环境正确注册。

桌面测试不能替代 iOS Safari 测试。

## 3. iOS 26 真机测试

### 安装与离线

- Safari HTTPS 首次加载。
- 添加到主屏幕并以 standalone 打开。
- 图标、名称、safe-area 和竖屏布局正常。
- 等待缓存完成后开启飞行模式，重新打开仍可用。
- 恢复网络后能取得新版本。

### 实时麦克风

- 首次允许权限。
- 首次拒绝后仍可选择录音。
- 停止按钮后系统麦克风指示结束。
- 退到后台后采集停止，返回可重新启动。
- 连续开始/停止 10 次无崩溃和重复流。
- 每根弦拨 5 次，与独立参考调音器对照。
- iOS 26.6.1：分别在 Safari 和主屏幕应用验证曾经能用、后来一直“正在听”的反馈；记录收音条是否随拨弦变化及具体提示。
- 授权后仍能正常采集；其他录音应用、通话或系统中断后能得到明确提示，再点开始可重新连接。
- 安静等待时显示无声/低音量提示，正常的安静环境不应被误报为系统中断。
- 发布 0.1.1 后，在旧版已安装 PWA 中点“立即更新”，确认底部为 v0.1.1，离线重开仍为新版本。

### 本地录音

- 语音备忘录默认 `.m4a`。
- 短 WAV、MP3。
- 文件名含中文和空格。
- 立体声、44.1 kHz 与 48 kHz。
- 纯静音、环境噪声、多根弦混在一起。
- 飞行模式下选择并分析本地录音。

## 4. 真琴测试协议

1. 用独立可信调音器把 G/C/E/A 调准。
2. iPhone 距琴约 20–40 cm，一次只拨一根弦。
3. 自动模式每根弦拨 5 次，记录 cents 与稳定时间。
4. 手动 G/C/E/A 各重复一次，确认不跳弦。
5. 将每根弦分别调低/调高约 10 cents，验证方向。
6. 在普通房间噪声下重复，观察是否返回不确定而非错误结果。
7. 使用语音备忘录录一根弦，再用文件入口分析并对照实时结果。

## 5. 可访问性与交互

- 触控目标至少约 44×44 CSS px。
- VoiceOver 能读出目标弦和状态，不因每帧更新持续打断。
- 动态字体放大时关键读数不截断。
- 不只依靠绿色/红色表达方向。
- reduced motion 下指针不使用强动画。
- 四个弦钮按钮顺序始终是 G/C/E/A，并有选中状态。

## 6. 性能目标

- 第一条有效反馈 ≤300 ms。
- 稳定反馈 ≤500 ms。
- UI 更新约 15–20 Hz，无明显长任务。
- 单次 YIN P95 小于分析 hop 间隔的 50%。
- 20 分钟实时运行不持续增长内存。
- 30 秒录音分析过程中页面仍能显示进度并响应取消。

## 7. P0 发布条件

以下任一失败都不能部署为稳定版：

- 四个目标任一稳定误差超过 ±3 cents。
- 强二次泛音持续造成倍频误判。
- 停止/后台后麦克风 track 未释放。
- 录音内容产生任何网络上传。
- iOS 26 无法添加到主屏幕或离线启动。
- 麦克风失败后无法使用录音入口。
- Service Worker 把用户永久锁在不可用旧版本。

## 8. 记录节奏

- 自动结果包括命令、通过/失败数量和环境。
- iPhone 未执行项写 `Pending: requires target device`。

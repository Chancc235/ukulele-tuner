# 实时麦克风故障处理与恢复

- 日期：2026-10-23。
- 反馈设备：iOS 26.6.1 iPhone。
- 反馈现象：同一个正式版本此前能用，现在点击“开始实时调音”后一直“正在听”，拨弦无反应。没有证据表明是应用或系统升级触发。
- 版本：线上 v0.1.0；本地修复 v0.1.1，尚未发布。

## 排查结论

1. 原有 22 项自动测试与静态检查通过，但没有覆盖浏览器授权后中断、运行中冻结和持续静音。
2. 读取到的线上 `src/microphone-source.js` 与仓库 HEAD 原版完全一致；本地完整 Git 历史和公开仓库中 `app/` 的提交记录都只有一次运行代码提交。
3. 原实现只在请求权限之前恢复 AudioContext，授权后不再验证状态；运行中也不检查音频状态、时钟进度和轨道是否有效。因此发生采集故障时，界面仍可能一直“正在听”。
4. [WebKit 291892](https://bugs.webkit.org/show_bug.cgi?id=291892) 记录过主屏幕应用返回前台后音频静默、甚至状态仍为 `running` 的情况。该记录只能支持检查这类路径，不能证明反馈中的 iOS 26.6.1 设备遇到了同一个系统问题。

没有在反馈设备上取得真实 PCM 或音频状态，因此本次修复关闭了已确认的处理缺口，不能宣称已确认或修复该设备的根因。

## 修复内容

- 在用户手势内调用恢复，同时立即请求麦克风，避免未完成的恢复 Promise 阻塞权限请求。
- 授权和建立连接后再次恢复并确认音频引擎运行；恢复最长等待 8 秒，等待权限期间可取消。
- 监听音频中断和轨道结束；音频时钟连续 3 秒冻结、轨道被关闭或持续 3 秒系统静音时，释放资源并提供重试提示。
- 用请求代号隔离旧的异步回调，取消后晚返回的流立即停止，不干扰新的会话。
- 显示收音音量和无声/低音量提示，区分没有声音输入、声音偏小、收到声音但没有稳定音高。
- 保持原有检测阈值、四弦配置和音高算法。版本为 0.1.1，缓存升级为 `uketune-v2`。
